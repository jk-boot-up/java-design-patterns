YouTube upload spec

How a pattern video goes from a project folder to YouTube. Each project's docs/youtube.md holds the title, description, chapters, tags and thumbnail; this spec says which files to upload, what to change on the way, and what to check before and after a video goes public. The step-by-step plan and the first video's ready-to-paste sheet are in youtube-upload-plan.md.

1. Which files are uploaded

The .m4a beside each video is an audio-only copy for listening offline; it is never part of an upload. Every video is narrated in the amy-slow voice (Piper en_US-amy-medium, speed 0.8); the older Kokoro builds have been deleted. Videos, audio and captions are never committed to git; they are uploaded from the local build only.

2. Rules for the uploaded text

  • No http:// or https:// in the description. Every scheme prefix is removed, so the repository link reads as a bare address: github.com/jk-boot-up/java-design-patterns/tree/main/gradle-java/.... YouTube refused descriptions carrying URLs on this channel. The Markdown files may keep full links for readers on GitHub; the stripping happens on the text sent to YouTube.
  • No < or > characters in the title or description: YouTube rejects them.
  • The first sentence is the name and the plain definition ("X pattern in Java: …"), as docs/youtube.md already has it.
  • Chapters must match the uploaded video. They are timed from the uploaded video's own .srt. Some older docs/youtube.md files still carry chapters and a runtime from the deleted Kokoro build; until those are regenerated, recompute the chapters from the amy-slow .srt at upload time. The first chapter is 00:00, and there are at least three, or YouTube shows no chapters.
  • Title at most 100 characters (aim for 60, which survives search results); description at most 5,000 characters; tags at most 500 characters in total.

4. Ways to upload

  1. The scripted uploader, tools/ytupload/ytupload.sh (the method in use). It drives YouTube Studio in a dedicated Chrome window (ytupload.sh chrome) that the channel owner signed in to by hand; it never types a password. It is run only when the channel owner asks for uploads.
  2. sheet <project> prints what would be uploaded;
  3. upload <project> attaches the .mp4, fills every field of section 3, and stops on the Visibility page; resume <project> continues a draft after a failed step without attaching the video again;
  4. publish chooses Public, ticks instant Premiere, saves, prints the link and closes the "Video published" dialog;
  5. sync reads the channel's video list and records every link it can match to a project;
  6. batch <category-or-project>... uploads and publishes many projects in turn (section 8);
  7. no-paid-promotion <video-id> fixes that answer on a video already published.
  8. YouTube Studio by hand, from the upload sheet (section 6), with the same settings.
  9. YouTube Data API script is not used: videos uploaded through an API project that has not passed Google's audit stay locked private, and these videos are published as Public.

5. Checks

Videos are saved as Public directly, so the checks are split around the save.

Before saving:

  • The description has no http://, https://, < or >.
  • Chapters come from the .srt of the uploaded file, start at 00:00, and the last chapter starts before the video's end.
  • The thumbnail is the project's docs/thumbnail.png, not an auto-picked frame.
  • Audience is "No, it's not made for kids", paid promotion is "No", and altered content (AI use) is "No".
  • The captions are attached, if used.

After saving:

  • Captions show at the right moments at three points in the video (start, middle, end).
  • 1080p processing has finished before the link is shared: code slides are unreadable at 360p.
  • Watch the first and last minute: audio clean, credit line present, no "next pattern" teaser.
  • If anything is wrong, fix it in Studio; switch to Private only if the fix needs a new upload.

6. The upload sheet

Before each upload, a sheet is prepared from docs/youtube.md: the title, the description with schemes removed and chapters timed for the uploaded file, the tags, and the file paths above. This is mechanical and can be scripted from gradle-java/docs/make_youtube_docs.py (its chapters() reads the .srt; pointing it at the amy-slow .srt gives amy-slow chapters, and the cue count of the scenes must equal the .srt's cue count).

8. Uploading every project (batch rules)

  • Order: micro-services-design-patterns first, then the other categories under gradle-java/ one at a time, projects in alphabetical order within a category.
  • Never twice: before a batch, sync records every video already on the channel. A project whose title (from its docs/youtube.md) is already on the channel, or which already has a link in the registry, is skipped.
  • One video at a time: the page is never left while a file is still uploading, because leaving the page cancels the upload. The script waits for the upload to finish before publishing.
  • Thumbnail failure is not fatal: if attaching docs/thumbnail.png fails, the video is published without it and the miss is logged, so the thumbnail can be added by hand later. Every other setting must succeed, or that project is left as a draft, logged, and the batch moves on.
  • A failure never causes a duplicate: a project that fails after its file was attached is recorded in the registry as a draft (with its video ID and the failed step), so no later batch uploads it again. Drafts are finished with resume <project> then publish.
  • Daily limit: YouTube caps uploads per day. When Studio reports the limit, the batch waits (6 hours at a time) and carries on by itself; already-uploaded projects are skipped.
  • Unattended, and cheap to follow: the batch runs in the background across all categories. Progress is written, not watched: ~/.ytupload-chrome/status.txt holds a one-line summary (uploaded, failed, to go, last project), and ~/.ytupload-chrome/batch.log one line per project (its link, or the step that failed). They are read only occasionally, never polled.
  • The registry: every link is recorded in gradle-java/docs/youtube-links.json (project path, title, category, video ID, date). It is the single source for:
  • gradle-java/docs/youtube-links.md and its themed .html twin, the tracking document listing every pattern with its YouTube link, by category; and
  • the YouTube link beside each project in the repository's index.md / index.html (generated by gradle-java/docs/make_index.py). Both are regenerated after each batch.
