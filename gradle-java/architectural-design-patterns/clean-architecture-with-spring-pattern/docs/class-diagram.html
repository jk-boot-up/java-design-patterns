Reading The Diagram

AppConfig and BrokenAppConfig both return the identical new PlaceOrderInteractor(...) call. The classes on the right — every entity, use case and adapter — do not know, and could not tell you, whether they were constructed by a person or a container.

Application depends on both configuration classes, but never at the same time. AppConfig builds the context every other act uses; BrokenAppConfig is only ever built as its own separate, short-lived context, in act five, specifically to fail.
