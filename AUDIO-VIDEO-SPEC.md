# Audio and Video Specification

This spec applies to **every project** in this repository: the teaching videos, their
audio-only editions, and the narration of the interactive animations. Progress in bringing
every project into line is tracked in [`ROLLOUT-REPORT.md`](ROLLOUT-REPORT.md).

## 1. One shared pipeline

- All audio and video are generated by the shared library [`tools/videokit`](tools/videokit/README.md).
  Projects do not carry their own copy of the pipeline.
- A project's `video/` folder keeps only its content:
  - `scenes.py`: the narration script and the slide settings;
  - `videokit.toml`: the voice;
  - `make_slides.py`: only if it draws custom diagram slides;
  - `make_subtitles.py`: only for its caption splitter.
- `build_video.sh` is a one-line call into the library.
- One command rebuilds everything: `tools/videokit/videokit.sh all <project>`.

## 2. The voice

**New projects use the amy-slow voice**, and only that voice:

| Setting | Value |
| --- | --- |
| Engine | Piper (open source, MIT) |
| Voice | `en_US-amy-medium`, US English, female |
| Speed | 0.8 (slower than normal, for beginners listening without a screen) |
| Pauses | `sentence_gap = 0.7`, `pause_scale = 1.5` |
| Loudness | −16 LUFS integrated, peaks limited to −1.5 dBFS |

It goes in the project's `video/videokit.toml`, which `tools/patternkit` writes when it
scaffolds a project, so a new project needs no separate `amy-slow` version.

**The original projects keep their first voice** and carry amy-slow as a second version
beside it (`video/videokit-amy-slow.toml`, outputs with an `-amy-slow` suffix). That first
voice was:

| Setting | Value |
| --- | --- |
| Engine | Kokoro v1.0 (open source, Apache 2.0) |
| Voice | `af_bella`, US English, female |
| Speed | 0.9 (a little slower than normal, for teaching) |
| Pauses | about 0.45 s after each sentence; `[[slnc N]]` in the script for longer ones |
| Loudness | −16 LUFS integrated, peaks limited to −1.5 dBFS |

This is "sample 03" from the voice auditions kept in
`gradle-java/micro-services-design-patterns/api-gateway-with-spring-cloud-gateway-pattern/video/voice-samples/`.

## 3. Wording rules

1. **The credit is always third person.** The narrating voice is female and the author is
   male. So no audio ever says "I am Jayasekhar Konduru", and the voice never speaks as him.
   The credit line is: *"This video is presented by Jayasekhar Konduru."*
2. **Avoid first person generally.** Write "the verdict", not "my verdict", and "the advice
   here is", not "I recommend".
3. **ID means identifier.** "ID", "id" and names like `orderId` are spoken "I D".
   videokit does this at speech time, so captions keep the written form.
4. **Numbers and symbols are spoken as words**, the way a person would say them aloud:
   - status codes: "four hundred and one", "five oh three";
   - paths: "slash api, slash pricing";
   - versions: "four point one".

## 4. Written for listening

The audience must be able to follow with **no screen at all**.

- Never point at the picture. No "as you can see", "here", or "this box".
- Name the actors. Say what each one does, and describe the flow in order.
- Use short sentences, one idea at a time, and plain words. The audience is beginners.
- Explain like a teacher, not a reader:
  - open a topic with a question or an everyday analogy (any domain may be used for analogies);
  - then give the worked example in the online-store domain;
  - pause after each key point.
- **Opening order:**
  1. What the video is: "This video explains the X pattern, in Java."
  2. The credit: "This video is presented by Jayasekhar Konduru."
  3. A plain, general definition.
  4. The same idea taught in the online store.
- **Closing:** restate the lesson in one sentence, point to the repository, invite a like
  and a subscribe, and say thanks. Never name the next pattern.

## 5. Animations and HTML

- **Every animation speaks in the amy-slow voice only**, spoken from the animation's own step
  text. `videokit.sh animation <project>` renders the clips (git-ignored, cached) and injects
  the player between `videokit:narration` markers in `docs/animation.html`. A project whose
  main voice is amy-slow uses `docs/audio/`; an original project whose video keeps its first
  voice has its animation play `docs/audio-amy-slow/` instead.
- The same injection adds the shared **UX layer** (`tools/videokit/videokit/web/ux.js`), so
  every animation behaves alike:
  - a **Light / Dim / Dark** theme switch, remembered per viewer (it starts from the
    system's light or dark setting). The page's own colours are rewritten as `--vk-*`
    variables when it is injected, and each theme remaps that palette;
  - a clickable **timeline** of the steps, a **Back** button and a progress bar;
  - **Predict first**: before each step the learner is shown what comes next and asked
    to guess what will happen, then reveals it;
  - **keyboard** control: arrows, Space, 1–9, R, N and P;
  - a short glow on whatever just changed, console lines that slide in, and an
    **All steps** list for revisiting any step;
  - no sideways scrolling at phone width, and no motion when the viewer asks for less.
- Every animation has a **Narration on/off** toggle (remembered per browser) and a
  **Play / Pause / Resume step** button for the narration of the step on screen. The page's
  own Step / Play / Reset buttons still drive the steps.
- Narration audio is **never embedded** in the HTML: it sits beside the page in `docs/audio/`,
  so the committed pages stay small. Without the clips the page still works, silently.
- Every other HTML file is **self-contained**: styles, scripts and images are embedded,
  with nothing linked from outside the file.
- Diagrams are SVG or PNG files in `docs/images/`. Mermaid is not used; the old Mermaid
  source blocks are removed by `gradle-java/docs/strip_mermaid.py`.

## 6. Quality gates

A build fails, rather than shipping a bad video, if any of these is wrong:

- **Continuous audio:** there is no gap anywhere in the audio timeline.
- **Credit line:** the narration contains no "I am Jayasekhar" or "I'm Jayasekhar".
- **Captions:** they are timed from the recorded start and end of each phrase.
